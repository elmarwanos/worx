Technical SEO to get right before launch day

Most ranking problems on a new site are decided before it goes live. This is the checklist we run so launch day starts from a clean slate.

A beautiful new website can still launch invisible. The usual causes are not mysterious algorithm changes but small technical oversights: a staging setting left on, redirects that were never mapped, pages that all share the same title. None of them are hard to fix. They are just easy to forget.

01

Let search engines in

Staging sites are, rightly, hidden from search engines. The most common launch mistake is carrying that setting into production. Before go-live we check:

  • robots.txtAllows crawling of everything that should be public, and points to the sitemap.
  • No stray noindexNo page-level noindex tags or headers left over from staging.
  • XML sitemapLists only real, canonical, indexable pages, and is submitted in Search Console.
  • One version of the siteHTTP, HTTPS, www and non-www all resolve to a single preferred address.
02

Moving from an old site

If the new site replaces an existing one, the old URLs have history: links pointing at them, rankings attached to them, bookmarks. Every one that changes needs a permanent (301) redirect to its closest new equivalent, not to the home page.

We build the redirect map from the old sitemap, analytics and backlink data before launch, test it on staging, and keep it in place for good. It is the single biggest factor in whether a redesign keeps its traffic.

A redesign without a redirect map is a new website that has to earn every ranking again from zero.

03

Every page, properly labelled

Each page should tell search engines clearly what it is. That means a unique title and meta description written for people, one clear H1, a canonical URL, descriptive alt text on meaningful images, and structured data where it fits: Organization on the home page, Service on service pages, Article on posts.

For bilingual sites, hreflang tags connect each English page to its Arabic counterpart so the right version shows in the right market.

Performance belongs on this list too. Core Web Vitals are measured on real visits, so a heavy launch build shows up in the data within weeks.

Rule of thumb Check twice, launch once.

Every item here is cheaper before go-live than after.

04

The first two weeks

Launch is the start of monitoring, not the end of the project. In the first two weeks we watch Search Console for crawl errors and indexing, follow up on any 404s the redirect map missed, compare traffic against the old site's baseline and fix what surfaces while it is still small.
